## 3. รายละเอียดการช่วยเหลือของ AI

### 3.1 Gemini (Google)

**การเขียน Automated Test (CP16)**

ให้คำแนะนำในการเขียนชุดทดสอบ 6 เคสด้วย `supertest` และ `node:test` ในไฟล์ `tests/api.test.js` ครอบคลุม

- การตรวจสอบ HTTP Status Code (`200`, `201`, `400`, `404`)
- การตรวจสอบรูปแบบข้อมูลที่ได้รับกลับมาเป็น Array
- การตรวจสอบ CORS Headers

**การทำ Bonus Challenge (Challenge 1–3)**

| Challenge | สิ่งที่ AI ช่วย | ไฟล์ที่เกี่ยวข้อง |
|---|---|---|
| 1 | แนะนำการสร้าง `AppError` สำหรับกำหนด Status Code และการซ่อน Stack Trace ใน Production ฝั่ง Backend | `errorHandler.js` |
| 2 | ให้ฟังก์ชัน `asyncHandler` เพื่อดักจับ Async Error ใน Express Routes | `requestRoutes.js` |
| 3 | ออกแบบระบบ Retry อัตโนมัติแบบ Exponential Backoff เมื่อเจอ Network/Server Error ฝั่ง React | `apiClient.js` |

### 3.2 Claude (Anthropic)

**การตรวจทานเอกสาร API Contract**

- ตรวจสอบความครบถ้วนของเอกสาร `API_CONTRACT.md` เทียบกับเช็คลิสต์ที่กำหนด
- ชี้จุดที่ยังไม่ได้แก้ไข ได้แก่ บล็อกคำอธิบายสำหรับผู้เขียน (`>`) ที่ยังไม่ได้ลบ และวงเล็บ `< >` ที่ยังค้างอยู่ในช่องผู้จัดทำ วันที่ปรับปรุง และตารางประวัติการเปลี่ยนแปลง
- จัดรูปแบบเอกสารฉบับสมบูรณ์พร้อมส่ง

**การจัดทำเอกสารสรุปผลการทดสอบ**

- จัดทำโครงสร้างไฟล์ `API_TEST.md` ประกอบด้วยตารางรายการเคสทดสอบทั้ง 6 เคส วิธีรันชุดทดสอบ และตารางสรุปผลพร้อมช่องแนบหลักฐานภาพหน้าจอ (Code และ Terminal Output) แยกรายเคส
- เพิ่มหมายเหตุข้อควรระวังในการรันทดสอบ เช่น การอ้างอิง `REQ-001` และ `REQ-999` ต้องสอดคล้องกับข้อมูล seed

## 4. การตรวจสอบและความถูกต้อง

โค้ดทั้งหมดผ่านการทดสอบและตรวจสอบความถูกต้องด้วยตนเอง ดังนี้

| วิธีตรวจสอบ | คำสั่ง | ผลลัพธ์ |
|---|---|---|
| รันชุดทดสอบอัตโนมัติ | `npm test` | ผ่านครบทุกเคส |
| ตรวจสอบเกณฑ์ประจำสัปดาห์ | `node check-week07.mjs` | ผ่านเกณฑ์สมบูรณ์ **36/36 รายการ** |

ข้อเสนอแนะทั้งหมดจาก AI ผ่านการอ่าน ทำความเข้าใจ และปรับแก้ให้เข้ากับโครงสร้างโปรเจกต์จริงก่อนนำไปใช้ ไม่ได้คัดลอกมาใช้โดยตรง
